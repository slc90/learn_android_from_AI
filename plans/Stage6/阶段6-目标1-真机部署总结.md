# Stage 6 - 目标 1 总结：将 Android 项目部署到真实设备

## 目标

能够把前面阶段的 Android 项目部署到真实 Android 设备上，并确认应用可以正常安装和运行。

---

## 本次使用环境

- 开发工具：Android Studio
- 电脑系统：Windows
- 真机：Redmi K40
- Android Studio 中识别的设备名：Xiaomi M2012K11AC
- 连接方式：USB
- 调试工具：ADB（Android Debug Bridge）

---

## 基本链路

真机运行时，可以把过程理解为：

```text
Android Studio
    ↓
构建 App
    ↓
ADB
    ↓
真实 Android 设备
    ↓
安装并启动 App
```

ADB 是电脑与 Android 设备之间的开发通信工具。Android Studio 会通过它完成应用安装、启动、日志查看和调试等操作。

---

## 实际操作过程

### 1. 手机开启开发者选项

在手机中开启：

- 开发者选项
- USB 调试

第一次连接新的开发电脑时，手机还可能弹出 USB 调试授权，需要允许该电脑进行调试。

---

### 2. USB 连接手机和电脑

使用支持数据传输的 USB 线连接手机。

Android Studio 一开始虽然能在 USB 扫描中看到 `Redmi K40`，但提示：

```text
Found USB device(s) not recognized as Android devices
```

这说明：

```text
Windows 能看到手机
        ↓
但 ADB 还没有识别到它
```

所以“系统识别到 USB 设备”和“ADB 能调试 Android 设备”不是同一件事。

---

### 3. 使用 adb devices 检查连接

ADB 位于 Android SDK 的：

```text
<Android SDK Location>\platform-tools
```

本机常见路径类似：

```text
C:\Users\mdrs\AppData\Local\Android\Sdk\platform-tools
```

将 `platform-tools` 加入 Windows 的 `Path` 后，可以直接执行：

```powershell
adb devices
```

最开始得到：

```text
List of devices attached
```

下面没有任何设备，说明 ADB 当时没有识别到手机。

---

### 4. 修正手机调试状态

确认手机上的：

- 开发者选项已开启
- USB 调试已开启
- 已允许当前电脑进行 USB 调试

之后 ADB 连接恢复正常，Android Studio 的设备选择框中出现：

```text
Xiaomi M2012K11AC
```

这说明 Android Studio 已经可以把 Redmi K40 当作运行目标。

---

### 5. 直接运行项目

在 Android Studio 中选择：

```text
Xiaomi M2012K11AC
```

然后点击绿色 Run 按钮。

项目成功：

```text
构建
→ 通过 ADB 安装到 Redmi K40
→ 启动 App
```

最终 App 已经在真机上正常运行。

---

## 这次遇到的问题

### Android Studio 能看到 Redmi K40，但不能选择运行

原因不是项目代码问题，而是：

```text
USB 层识别成功
ADB 调试层没有建立
```

判断这类问题最直接的方法是：

```powershell
adb devices
```

如果设备列表为空，就先解决 ADB / USB 调试连接，而不是继续排查 Gradle、Compose 或应用代码。

---

## 一个容易混淆的点

开发者选项是开启在手机上的，本身不因为更换电脑而必须重新开启。

但连接新的开发电脑时，通常需要重新授权该电脑的 ADB 调试权限，因为不同电脑使用不同的 ADB RSA 密钥。

---

## 目标 1 完成标准

本次已经完成：

- 真机开启开发者选项和 USB 调试
- 电脑能够通过 ADB 识别 Redmi K40
- Android Studio 能选择 Xiaomi M2012K11AC 作为目标设备
- 项目能够成功安装到真机
- App 能够在真机上正常启动和运行

因此，Stage 6 的目标 1 已完成。
