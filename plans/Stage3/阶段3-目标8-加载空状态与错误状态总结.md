# 阶段 3 - 目标 8：加载、空状态与错误状态

## 目标

能够处理常见的 UI 状态：

- Loading：正在加载
- Empty：加载成功，但没有数据
- Error：加载失败
- Content：正常显示内容

核心思路是：

> 页面不直接“操作 UI”，而是根据当前状态决定显示什么。

---

## 1. 用 sealed interface 表示页面状态

文件：

```text
app/src/main/java/com/example/learnandroidfromai/Stage3ViewModel.kt
```

定义：

```kotlin
sealed interface StudyUiState {

    data object Loading : StudyUiState

    data object Empty : StudyUiState

    data class Error(
        val message: String
    ) : StudyUiState

    data class Content(
        val articles: List<String>
    ) : StudyUiState
}
```

可以把它理解成：

```text
StudyUiState
├── Loading
├── Empty
├── Error(message)
└── Content(articles)
```

这里：

- `data object` 表示单例状态，不需要额外数据。
- `data class` 表示这种状态还需要携带数据。
- `sealed interface` 限定了这一组状态的可能类型。

它和 Rust 的：

```rust
enum StudyUiState {
    Loading,
    Empty,
    Error(String),
    Content(Vec<String>),
}
```

表达的是类似的问题，只是 Kotlin 使用 `sealed interface + data object/data class` 来实现。

## 2. `when` 根据状态决定显示什么

文件：

```text
app/src/main/java/com/example/learnandroidfromai/Stage3Navigation.kt
```

核心代码：

```kotlin
when (val state = viewModel.uiState) {

    StudyUiState.Loading -> {
        Text("正在加载...")
    }

    StudyUiState.Empty -> {
        Text("暂无内容")
    }

    is StudyUiState.Error -> {
        Text("错误：${state.message}")
    }

    is StudyUiState.Content -> {
        Column {
            state.articles.forEach { article ->
                Text(article)
            }
        }
    }
}
```

其中：

```kotlin
is StudyUiState.Error
```

表示：

> 判断 `state` 是否是 `StudyUiState.Error` 类型。

进入这个分支以后，Kotlin 会进行 smart cast，因此可以直接访问：

```kotlin
state.message
```

同理：

```kotlin
is StudyUiState.Content
```

之后可以直接使用：

```kotlin
state.articles
```

而 `Loading` 和 `Empty` 是 `object` 单例，因此直接比较对象即可：

```kotlin
StudyUiState.Loading
StudyUiState.Empty
```

## 3. ViewModel 持有当前 UI 状态

在 `StudyViewModel` 中：

```kotlin
class StudyViewModel : ViewModel() {

    var uiState by mutableStateOf<StudyUiState>(
        StudyUiState.Loading
    )
        private set
}
```

这里的意思是：

```text
StudyViewModel
    ↓
持有当前 StudyUiState
    ↓
Compose 观察这个状态
    ↓
状态变化时重新绘制 UI
```

`private set` 表示：

- UI 可以读取 `uiState`
- UI 不能直接修改 `uiState`
- 状态变化由 ViewModel 控制

## 4. 模拟异步加载

增加：

```kotlin
import androidx.lifecycle.viewModelScope
import kotlinx.coroutines.delay
import kotlinx.coroutines.launch
```

然后：

```kotlin
init {
    loadArticles()
}
```

加载逻辑：

```kotlin
fun loadArticles() {
    viewModelScope.launch {
        uiState = StudyUiState.Loading

        delay(2000)

        val articles = listOf(
            "Android",
            "Kotlin",
            "Jetpack Compose"
        )

        uiState =
            if (articles.isEmpty()) {
                StudyUiState.Empty
            } else {
                StudyUiState.Content(articles)
            }
    }
}
```

运行时：

```text
进入页面
   ↓
Loading
   ↓
等待 2 秒
   ↓
Content
```

如果：

```kotlin
val articles = emptyList<String>()
```

则：

```text
Loading
   ↓
Empty
```

## 5. Error 状态

可以暂时用异常模拟失败：

```kotlin
fun loadArticles() {
    viewModelScope.launch {
        uiState = StudyUiState.Loading

        delay(2000)

        try {
            throw Exception("服务器连接失败")
        } catch (e: Exception) {
            uiState = StudyUiState.Error(
                message = e.message ?: "未知错误"
            )
        }
    }
}
```

状态变化：

```text
Loading
   ↓
加载失败
   ↓
Error(message)
```

UI：

```kotlin
is StudyUiState.Error -> {
    Text("错误：${state.message}")
}
```

## 6. 重试

Error 状态通常需要给用户一个重试入口：

```kotlin
is StudyUiState.Error -> {
    Column {
        Text("错误：${state.message}")

        Button(
            onClick = viewModel::loadArticles
        ) {
            Text("重试")
        }
    }
}
```

流程：

```text
Loading
   ↓
Error
   ↓
用户点击“重试”
   ↓
loadArticles()
   ↓
Loading
   ↓
重新加载
```

## 7. 最终状态模型

这一节最后形成的基本状态机：

```text
            ┌─────────┐
            │ Loading │
            └────┬────┘
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    Content    Empty      Error
                         │
                         │ 重试
                         └────→ Loading
```

重要的是：

- `Empty` 不等于 `Error`
- `Empty` 表示加载成功，只是结果为空
- `Error` 表示加载过程本身失败
- UI 只根据状态绘制
- ViewModel 负责修改状态

## 8. 关于协程

这一节使用：

```kotlin
viewModelScope.launch {
    ...
}
```

来启动协程。

当前示例中：

```kotlin
delay(2000)
```

会挂起协程，但不会像：

```kotlin
Thread.sleep(2000)
```

那样阻塞主线程。

因此在等待期间，UI 仍然可以正常绘制和响应。

这里暂时只需要记住：

```text
launch      → 启动协程，不关心返回值
async/await → 启动协程，并取得返回值
suspend     → 函数可以挂起协程，不阻塞线程
```

协程的 Dispatcher、线程切换与并行问题不属于本节主线，后续需要时再展开。

## 本节完成标准

能够理解并实现：

```text
Loading
Empty
Error
Content
```

这几种常见页面状态，并做到：

```text
ViewModel 修改状态
        ↓
Compose 观察状态
        ↓
when 根据状态选择 UI
```

最终目标不是让 UI 自己判断业务过程，而是：

> ViewModel 决定“现在是什么状态”，Compose 负责“这个状态应该画成什么样”。
