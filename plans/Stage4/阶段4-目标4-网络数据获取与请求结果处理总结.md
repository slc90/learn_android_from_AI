# Stage 4 · 目标 4：从网络获取数据并处理请求结果

## 1. 本节目标

这一节完成了 Android 网络请求的完整入门链路：

```text
Compose UI
→ ViewModel
→ Repository
→ Retrofit
→ HTTP
→ Server
```

服务器返回数据后：

```text
Server
→ HTTP Response
→ Retrofit
→ Kotlin DTO
→ Repository
→ ViewModel
→ StateFlow
→ Compose
```

最终实践了：

- 配置 Retrofit
- 配置 Kotlin Serialization
- 声明网络接口
- 发起 GET 请求
- 使用路径参数 `@Path`
- 使用查询参数 `@Query`
- 发起 POST 请求
- 使用请求体 `@Body`
- 区分请求 DTO 与响应 DTO
- 获取单条网络数据
- 获取列表网络数据
- 处理 Loading / Success / Error
- 区分 HTTP 错误与网络异常
- 使用 `Response<T>` 自己读取 HTTP 响应
- 将网络数据通过 StateFlow 驱动 Compose UI
- 使用 LazyColumn 展示网络返回的列表

## 3. Retrofit 的作用

Retrofit 用来描述并执行 HTTP API。

核心接口：

```kotlin
interface TodoApiService {

    @GET("todos/{id}")
    suspend fun getTodo(
        @Path("id") id: Int
    ): Response<TodoDto>
}
```

这里：

```kotlin
@GET("todos/{id}")
```

表示 GET 请求。

```kotlin
@Path("id") id: Int
```

会替换 URL 中的：

```text
{id}
```

例如：

```kotlin
getTodo(3)
```

最终对应：

```text
GET /todos/3
```

---

## 4. RetrofitClient

本节使用一个 Kotlin `object` 保存 Retrofit 实例：

```kotlin
object RetrofitClient
```

`object` 本身就是单例。

核心结构：

```kotlin
object RetrofitClient {

    private val json = Json {
        ignoreUnknownKeys = true
    }

    private val retrofit = Retrofit.Builder()
        .baseUrl("https://jsonplaceholder.typicode.com/")
        .addConverterFactory(
            json.asConverterFactory(
                "application/json".toMediaType()
            )
        )
        .build()

    val todoApi: TodoApiService =
        retrofit.create(TodoApiService::class.java)
}
```

其中：

```kotlin
.baseUrl(...)
```

定义服务器基础地址。

而：

```kotlin
retrofit.create(TodoApiService::class.java)
```

会根据 `TodoApiService` 的声明生成真正可调用的实现对象。

## 5. DTO

DTO 全称：

```text
Data Transfer Object
```

中文通常叫：

```text
数据传输对象
```

本节响应 DTO：

```kotlin
@Serializable
data class TodoDto(
    val userId: Int,
    val id: Int,
    val title: String,
    val completed: Boolean
)
```

它用来描述服务器响应 JSON 的结构。

例如服务器返回：

```json
{
  "userId": 1,
  "id": 1,
  "title": "delectus aut autem",
  "completed": false
}
```

会被 Kotlin Serialization 转换为：

```kotlin
TodoDto(...)
```

---

## 6. DTO 与 Entity 的区别

上一节 Room 中：

```text
TaskEntity
```

表示数据库中的数据结构。

这一节：

```text
TodoDto
```

表示网络传输中的数据结构。

可以简单理解为：

```text
Entity → 数据库存储
DTO    → 网络传输
```

两者职责不同，即使字段暂时很像，也不应该默认视为同一个概念。

## 7. Repository 调用网络接口

本节使用：

```kotlin
class TodoRepository
```

让 ViewModel 不直接依赖 Retrofit。

例如：

```kotlin
suspend fun getTodo(id: Int): Response<TodoDto> {

```

因此调用链：

```text
ViewModel
↓
Repository
↓
TodoApiService
↓
Retrofit
```

和 Room 那节保持了相同的分层思路。

## 9. ViewModel 中执行网络请求

网络接口是：

```kotlin
suspend fun
```

所以需要在协程中调用。

本节使用：

```kotlin
viewModelScope.launch {
    ...
}
```

例如：

```kotlin
viewModelScope.launch {
    val response = repository.getTodo(id)
}
```

这样网络请求由 ViewModel 自己的协程作用域管理。

## 10. 网络数据驱动 UI

定义：

```kotlin
data class TodoUiState(
    val isLoading: Boolean = false,
    val todo: TodoDto? = null,
    val todos: List<TodoDto> = emptyList(),
    val errorMessage: String? = null
)
```

ViewModel 使用：

```kotlin
private val _uiState =
    MutableStateFlow(TodoUiState())

val uiState =
    _uiState.asStateFlow()
```

Compose 中：

```kotlin
val todoUiState by
    todoViewModel.uiState.collectAsState()
```

网络响应回来后更新：

```kotlin
_uiState.update {
    it.copy(
        isLoading = false,
        todo = todo
    )
}
```

最终形成：

```text
网络响应
↓
TodoDto
↓
ViewModel
↓
StateFlow
↓
Compose 重组
↓
UI 更新
```

## 11. Loading / Success / Error

网络请求不能只考虑成功。

本节使用三个基本状态：

```text
Loading
Success
Error
```

对应：

```kotlin
data class TodoUiState(
    val isLoading: Boolean = false,
    val todo: TodoDto? = null,
    val errorMessage: String? = null
)
```

请求开始时：

```kotlin
_uiState.update {
    it.copy(
        isLoading = true,
        errorMessage = null
    )
}
```

成功时：

```kotlin
_uiState.update {
    it.copy(
        isLoading = false,
        todo = todo,
        errorMessage = null
    )
}
```

失败时：

```kotlin
_uiState.update {
    it.copy(
        isLoading = false,
        errorMessage = ...
    )
}
```

Compose 根据状态决定显示：

```text
正在加载...
```

或网络数据，或错误信息。

## 12. 使用 `Response<T>` 获取完整 HTTP 响应

最开始：

```kotlin
suspend fun getTodo(id: Int): TodoDto
```

后来改成：

```kotlin
suspend fun getTodo(id: Int): Response<TodoDto>
```

区别在于：

```text
TodoDto
```

只拿最终解析后的数据。

而：

```text
Response<TodoDto>
```

可以访问整个 HTTP 响应。

例如：

```kotlin
response.isSuccessful
response.code()
response.body()
response.headers()
response.errorBody()
```

---

## 13. HTTP 错误与网络异常

这是本节比较重要的区分。

### 有 HTTP 响应

例如：

```text
404
500
```

服务器已经返回了一个 HTTP Response。

因此可以：

```kotlin
if (response.isSuccessful) {
    ...
} else {
    val code = response.code()
}
```

例如：

```text
HTTP 404
```

走的是 `if / else` 分支。

---

### 没有拿到 HTTP 响应

例如：

```text
断网
DNS 失败
连接失败
超时
```

这时根本没有：

```text
Response
```

而是直接抛异常。

例如：

```kotlin
catch (e: IOException) {
    ...
}
```

因此：

```text
有 HTTP Response
→ 检查状态码

没有 HTTP Response
→ 捕获网络异常
```

这是两类不同的问题。


## 15. 查询参数 `@Query`

接口：

```kotlin
@GET("todos")
suspend fun getTodosByUser(
    @Query("userId") userId: Int
): Response<List<TodoDto>>
```

调用：

```kotlin
getTodosByUser(1)
```

相当于：

```text
GET /todos?userId=1
```

因此：

```text
@Path  → URL 路径的一部分
@Query → URL ? 后面的查询参数
```

## 16. 获取网络列表

单条数据返回：

```kotlin
Response<TodoDto>
```

列表数据返回：

```kotlin
Response<List<TodoDto>>
```

例如：

```kotlin
val response =
    repository.getTodosByUser(1)
```

成功后：

```kotlin
val todos =
    response.body() ?: emptyList()
```

本节实际得到：

```text
20 条 Todo
```

## 17. 网络列表驱动 LazyColumn

ViewModel 保存：

```kotlin
val todos: List<TodoDto>
```

Compose：

```kotlin
LazyColumn {
    items(todoUiState.todos) { todo ->
        Text(
            text = "${todo.id}. ${todo.title}"
        )
    }
}
```

因此：

```text
网络 List<TodoDto>
↓
StateFlow
↓
LazyColumn
↓
一条 Todo 对应一个 item
```

这和之前使用本地数据驱动列表的思路是一致的。

## 19. 请求 DTO 与响应 DTO

本节后来把两者分开。

请求：

```kotlin
@Serializable
data class CreateTodoRequest(
    val userId: Int,
    val title: String,
    val completed: Boolean
)
```

响应：

```kotlin
@Serializable
data class TodoDto(
    val userId: Int,
    val id: Int,
    val title: String,
    val completed: Boolean
)
```

原因之一是：

```text
id
```

通常由服务器创建资源后产生。

因此客户端创建请求不一定应该提供：

```kotlin
id
```

最终结构：

```text
POST

CreateTodoRequest
↓
Server
↓
TodoDto
```

---

## 20. JSONPlaceholder 的 POST 特点

本节使用 JSONPlaceholder 作为练习服务器。

POST `/todos` 后返回：

```text
id = 201
```

但这个接口只是模拟创建成功。

它不会真的把新 Todo 永久写入服务器数据库。

因此连续创建时，不应该把：

```text
201
```

理解成真实数据库不断增长的主键。

本节只利用它验证：

```text
请求体发出成功
+
服务器响应成功
+
响应能够被 Retrofit 解析
```

## 22. 本节最终心智模型

```text

↓
ViewModel
↓
Repository
↓
Retrofit API
↓
HTTP
↓
Server
```

响应回来：

```text

↓
HTTP Response
↓
Retrofit
↓
DTO
↓
Repository
↓
ViewModel
↓
StateFlow
↓
Compose
```

请求结果：

```text
请求开始
↓
Loading

拿到 HTTP Response
├── 2xx
│   ↓
│ Success
│
└── 4xx / 5xx
    ↓
    HTTP Error

没拿到 HTTP Response
↓
IOException 等网络异常
```
